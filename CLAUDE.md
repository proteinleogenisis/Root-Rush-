# Root Rush

Root Rush is a phone-first study game for an Algebra 2 class (St. Vrain Valley Schools, Big Ideas Algebra 2, Chapter 5: Rational Exponents and Radical Functions). It is live on GitHub Pages at https://proteinleogenisis.github.io/Root-Rush-/ and is used as a home-screen app on an iPhone and an iPad.

## How the student learns (follow these)
- Visual and interactive beats text. Prefer step-by-step reveals, color-coded math, and quick feedback.
- Calculators are allowed in class. Teach what to type and what the answer means, but homework and tests say "show your steps", so walkthroughs must show the written lines.
- Spot-the-mistake questions are not on tests. They are removed from play on purpose; do not add them back.
- Each day must be learned before moving on: skills are mastered, then a final quiz unlocks the next day.
- Rush for a day uses only that day's skills.
- When the student sends a new homework photo, check that every problem type on it is covered by a question generator and a Learn lesson, then add what is missing.

## Files
- `index.html`: the whole app (HTML, CSS, JS in one file). No build step.
- `icon.png`, `apple-touch-icon.png`, `manifest.webmanifest`: home-screen icon and app manifest.

## Code map (all in index.html)
- `GEN`: question generators, one per skill key. Each returns `{q, ex, c, w, why, walk}`; `walk` is an array of `[mathHtml, caption]` steps shown when an answer is wrong. Types: default multiple choice, `words` (text choices), `order` (tap steps in order, uses `steps` and `tiles`), `line` (number-line estimate), `spot` (unused in play).
- `TAGS`: display name per skill key. `LESSONS`: skill keys per day (`"5.1"`, `"5.2"`, `"5.3"`). `DAYS`, `DAY_ORDER`, `ROAD`: day metadata, order, and roadmap.
- `SKILLS`: rule card and example per skill for the home skill list.
- `LEARN51`, `LEARN52` (via `LEARNS`): Learn lessons, each mapped to homework problems, with step reveals and a "Your turn" check. A numbered lesson picker (`#lDots`) jumps to any finished lesson or the next unfinished one (later ones locked); a finished lesson shows "Already done: skip to next lesson".
- `LT`, `LT52`, `LT53`: lightning-round true/false items for 5.1, 5.2 and 5.3.
- Mastery: each skill has `xp` 0 to 100 (+20 right, +25 at combo x3 or more, -15 miss (`MX_LOSS`); Boost doubles gains; Shield blocks a loss). At 100 a skill is mastered (`m: true`) and skipped in runs.
- Final quiz: unlocked when every skill in a day is mastered. Homework-style questions, about two per skill (`HW_DAY`: [question type, skill]; `HW` holds quiz-only types that ask for the actual answer the way the homework does, e.g. "Solve 5x³ + 6 = 46", "Evaluate with a calculator"; the student rejected combined multi-skill questions), no timer, every answer must be right to pass; a tap only selects an answer and "Yes, lock it in" confirms it (`QUIZ_CONFIRM`, also for "I don't know") so a mis-tap can be fixed (`QUIZ_PASS_FRAC` = 1, the student asked for it to be aced). Passing sets `passed[day]` and unlocks the next day. Missed skills drop to 60 xp (`QUIZ_MISS_XP`) the moment the wrong answer is locked in, and every quiz answer counts as an attempt, so quitting mid-quiz or syncing an older copy from another device cannot undo a miss.
- Quick review: the Home card/button for it was removed at the student's request (Nov 16); `renderReview` now renders nothing. The spaced-schedule data (`due`, `iv`) is still kept.
- Review Rush (a passed day, every skill): a miss locks that skill in (`st.fix`) as "Rematch: X · n of 2 in a row" until it's right `FIX_STREAK` (2) times in a row, then back to all skills; a miss during the rematch resets the count.
- Homework checker (`#check`, `solver.js` = `RRSolve`, tests `node solver.test.mjs`): a visually quiet page from the "Check a homework answer" link on Home. Type a problem; it shows the exact answer (simplest radical form, rationalized), exponent form, a 2-decimal value and the solving steps. Handles evaluate, simplify (incl. like radicals, conjugates, variables assumed positive) and one-variable equations peeled from the outside in (±, no real solution, extraneous check). Last input is remembered (`hkLast`).
- Rush: 180 seconds, starts instantly (no 3-2-1). Lightning round is due at 90 seconds left but only starts after the current question is answered (`st.ltPending`, checked in `next()`); a wrong lightning answer ends the lightning round: "Not quite" plus the reason shows for `LT_WRONG_SHOW_MS` (3000 ms, lightning clock frozen; a "Got it" button skips ahead), then it goes straight back to normal Rush (the old 5 s lockout was removed at the student's request). Lightning items are tagged by skill (`LT_SK`, `LT52_SK`, `LT53_SK`, same order as `LT`/`LT52`; keep them in sync when adding items); `ltPool` uses the day's mastered skills, or with none mastered the struggling ones (missed this run or recent accuracy <= `LT_STRUGGLE_ACC`, else the `LT_STRUGGLE_MIN` lowest-xp skills); if no item matches it falls back to the whole list. Every skill has at least 5 lightning items (quick, a couple of seconds each, about 50/50 true/false); keep it that way when adding skills. Double points in the last 10 seconds, ghost of the day's best score.
- Typed answers (Nov 17, student's request; since Nov 18 ONLY in the final quiz, `TYPE_ONLY_IN_QUIZ`, Rush and training are multiple choice again): a question whose answer is math is typed on an on-screen keypad (`typeBox`, `typeKey`, `typeSubmit`; a real keyboard works too), not tapped. `typed.js` (`RRType`, tests `node typed.test.mjs`) decides `canType(c)` and `check(typed, c)`: same value (sets like "x = ±2" / "14 or 2" compared as sets, variables checked at sample points incl. negatives so |y| matters, 2-decimal answers within 0.0051) AND written at least as simply as the answer (no perfect power left in a root, reduced fractions and exponents, no negative exponents, no more operations than the answer). A right value that isn't simplified, or a close decimal for an exact answer, is a free retry with a hint, not a miss. Exceptions that stay multiple choice: word answers (`words`), step order, the number line, and `TYPE_CHOICE_KEYS` (`entry` keypress questions). Extra keys appear only when needed: the question's variable letters, |, ∜, "or" for equations, "No real" for skills that can have no real answer (`noRealKey`). Day 3 answers type too: function rules show a fixed "g(x) = " / "y = " in front (`RRType.prefix`) and are checked as functions at 16 sample points (−10..10), and domain/range answers like "x ≥ −3" are checked as inequalities (`rel`; "−3 ≤ x" also counts); "Domain: …; Range: …" pairs, point lists and transformation descriptions stay choices. While typing, the floating Calculator button is hidden (`body.typing`, it covered the bottom keys) and a Calculator key sits in the keypad. A fraction typed right after ^ is the whole exponent (`expFrac`: 7^1/4 = 7^(1/4), shown raised while typing) unless a letter, | or ( follows it (x^4/3|y| stays division). Lightning stays true/false. The wrong choices `w` are still used for the exception questions and were made harder the same day (every wrong choice is a real slip in the same format as the answer).
- "I don't know" button (`idk()`, top right of the question card in Rush/quiz, hidden in lightning): counts as a miss but costs `IDK_LOSS` (10) mastery instead of 15, and opens the walkthrough.
- Paper (`tape`, `tpAdd`, `tpRender`, `tpPrune`): inside the calculator, every "=" answer is saved newest-first; tap one to put it back in the calculator, × removes, Clear empties. Answers from earlier questions are removed on their own when the question changes. "Paper only" (`paperOnly`, remembered) hides the keypad and shows just the saved answers. (The finger-drawing paper was removed at the student's request.)

## Adding a new day (for example 5.3)
1. Add generators to `GEN`, each with a `walk`.
2. Add their keys to `TAGS`, `LESSONS["5.3"]`, and rule cards to `SKILLS` (with `L:"5.3"`).
3. Add `DAYS["5.3"]`, append `"5.3"` to `DAY_ORDER`, update `ROAD`, and set `LATEST`.
4. Add a `LEARN53` lesson list and register it in `LEARNS`.
5. Add lightning items and make `ltNext()` pick that day's list.
6. Test, then push.

## Testing
Headless Chrome with Playwright works well: load `file://.../index.html` at a 390x844 viewport, start runs, answer through `pickIdx`, and check `pageerror` events. Also stress each generator a few thousand times to confirm four distinct answer choices and no `undefined` or `NaN` in `walk`.

The casino floor is full screen on iPad too (`FULL_MAX_W` 4000; `.wrap` zoom is 1 while `body.cz-fs`); on screens wider than the drawing the scene is drawn wider instead (`fullWide()`, `sceneSvg(dir, can, tall, wide)`: the games stay in the middle 360 units, the room, lights, crowd, Salon bar, its stools (`STOOL_GAP`) and velvet ropes (`ROPE_GAP`, gap in the middle as the way in) extend to both sides), so it fills iPad landscape and portrait edge to edge. Drunkness keeps wearing off while the app is closed (it's computed from the drink's timestamp).
